# 否定之否定论证：TCE 改进是否有用？

## 反题阶段（尖锐攻击）
攻击1: 冷启动场景（每模式 3-8 观测）TCE 全部拒绝编译——保守到无用？
  实测: 旧点估计建议编 4 个（含运气噪声），TCE 拒绝全部。
攻击2: 若 TCE 与旧方法在数据充足时结论相同，整套贝叶斯就是过度工程，
  用 min_samples 一行代码就能实现"延迟决策"。
攻击3: Autonomy 默认 manual——反正要人审批，TCE 的自动化决策无意义。
攻击4: 决定性实验暴露 v2 致命伤——同均值异方差模式 LCB 相同，
  方差区分能力为零（名义方差非实证方差）。

## 第二次否定（合题的必要修正）
R7 Welford 实证方差: update_save 存真实样本方差, net_lcb/net_asym 使用之。

## 合题实证（决定性实验 DECISIVE_V2 修正后）
同均值(153k token)两模式:
  stable(恒3000x50): LCB=+31,576 → 编译
  volatile(5900/100交替x50): LCB=-97,930 → 不编译
旧点估计视角两者完全相同(15万)——TCE 在信息量相同的前提下做出了
质量更高的决策。这是"有用"的最强证明：不是替代判断，而是提升判断的信息利用率。

## 对攻击1/2/3 的回应
攻1: 周期重评机制下，拒绝不是永久拒绝而是延迟；错误编译的成本(100k token
  +噪声工具污染)远大于延迟一轮的机会成本。冷启动保守是理性。
攻2: 方差区分实验证明 TCE 与旧方法存在**永久性分歧场景**（同均值异方差）,
  min_samples 无法复现该能力。
攻3: manual 档下 TCE 输出的是带置信度与校准记录的证据链，提升的是**人工审批
  的决策质量**；且 autonomous 档位按 §8.1 需安全网挣得——TCE 正是安全网本体。

## 结论
TCE 有用，且其有用性的边界已被精确刻画：
- 高频高稳模式: 新旧一致（无需 TCE）
- 边际/波动模式: TLC 显著优于点估计（核心价值区）
- 冷启动小样本: TCE 保守拒绝（防过度工程）
