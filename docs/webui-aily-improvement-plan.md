# newbee WebUI 修改方案：工作空间、历史、协作与视觉收敛

日期：2026-09-17。状态：设计提案，本轮仅写方案，未实施产品改动。

## 1. 目标与证据

用户应能围绕同一件工作提出要求、检查产物、指导执行、协同和验收；程序员可以逐层深入到成员分工、文件、工具记录和执行会话。

依据：登录后的 Aily/妙搭页面走查与截图、4189 实际点击、newbee 当前源码。没有对生成质量、性能或多人并发进行对比测试。下文视觉数值是建议规格，不是 Aily 测量值。

| 已观察到的 Aily 交互 | 可以借鉴 | 证据边界 |
| --- | --- | --- |
| 首页按应用开发、创意设计和具体场景组织输入；点击 AI 工具后出现具体需求示例 | 用户先表达意图，再逐步细化 | 没有提交生成 |
| 概要设计有用户故事、功能点、页面结构编辑控件，同时允许对话修改 | 产物可以直接操作，不必全靠长提示词 | 没有提交编辑，未验证保存冲突 |
| 左侧对话、右侧设计/计划，计划有章节目录 | 保留沟通上下文，产物独立阅读 | 未测试全部窗口尺寸 |
| 点击关闭设计面板，左侧历史仍保留，右侧露出代码和日志 | 各面板独立，关闭不等于离开工作 | 键盘 Esc 测试超时，未验证通过 |
| 历史显示命名对话、继续当前对话、项目初始化 V1 和时间 | 区分讨论历史和产物版本 | 旧版本预览、比较与恢复尚未点通 |
| 工具过程折叠为“调用 3 次工具”，前后有阶段说明 | 默认看结论，需要时看证据 | 没有验证所有展开内容 |
| 生成中提示关闭页面不影响开发，完成后飞书通知 | 明确后台执行与离开后果 | 仅确认提示，未验证通知送达 |
| 全局搜索兼有快捷操作 | 内容搜索与命令入口可以统一 | 搜索工单未见已有应用结果，不列为成功案例 |

Aily 协同开发的成员邀请、权限、同时编辑、冲突处理尚未验证。本方案协同部分是对 newbee 的设计建议，不能描述成 Aily 已验证能力。本轮重新访问已回到登录页，未再次完成其内部交互走查。

截图在当前工作树 `.newbee/browser/`：aily-home.png、aily-project.png、aily-closed-detail.png、aily-examples.png、aily-import.png、aily-history.png。部分历史截图拍摄于加载中，以走查文字记录为补充。截图含用户项目信息，不应作为公开静态资源或提交附件。

## 2. newbee 的当前问题

- 4189 实测：工作卡进入详情需要“更多 → 查看工作”；待验收工作流卡没有直接可见的查看成果按钮。
- 待验收状态与“实施修改 · 5/6”“互评 0/2 轮”并列，用户动作与内部流程竞争注意力。
- 进入 login 工作后，顶部仍提示另一件工作的成果待验收，打断当前上下文。
- 顶栏、面包屑、筛选、卡片重复表达位置与状态；绝对目录路径占用首屏。
- 协作记录主要列出子工作和阶段，没有集中回答谁负责什么、当前等谁、交给谁验收。
- 已有执行检查、引用、关闭/Esc、展开与阅读位置机制，应扩展复用，不另造一套导航。
- CAS revision 是并发控制值，不能被包装成可恢复的成果历史版本。

## 3. 页面结构

列表保留“待我处理 / 进行中 / 已完成”。群聊与成员是辅助入口。标题直接打开工作；卡片主操作直接打开对应处理对象，避免所有动作藏在更多菜单。

```text
项目 / 工作名称                     等待你验收   [查看成果] [更多]
负责人 · 最近进展                   [历史] [协作成员]
┌────────────────────┬──────────────────────────────┐
│ 工作沟通与关键进展 │ 成果 / 计划 / 变更 / 执行证据   │
│ 要求与决定         │ 对象名称、版本、验证状态        │
│ 阶段摘要           │ 正文 / 差异 / 记录              │
│ 工具记录按需展开   │                                │
│ 补充本工作要求…    │ [展开 / 恢复分栏] [关闭 · Esc]  │
└────────────────────┴──────────────────────────────┘
```

没有打开对象时使用单列概览；打开成果、计划、执行证据时进入分栏。现有概览、协作记录、执行观察、成果验收四标签先保留，将相关入口接到同一套面板，稳定后再减少重复导航。

项目层看工作组合；工作层看目标、决定和产物；成员层看分工；执行层看工具与日志。每次下钻都保留工作身份和返回入口。

## 4. 状态、操作与输入

| 用户状态 | 主操作 | 输入提示 |
| --- | --- | --- |
| 待开始 | 查看计划；有明确计划后再开始 | 补充目标和约束 |
| 需要你决定 | 查看方案 | 对当前方案提出意见 |
| 执行中 | 查看进展 | 补充本工作要求 |
| 等你答复 | 回答并继续 | 回答具体阻塞问题 |
| 执行异常 | 查看原因；具备恢复条件后重试 | 补充恢复所需信息 |
| 已暂停 | 继续执行 | 修改继续执行前的要求 |
| 待验收 | 查看成果 | 对本次成果提出修改意见 |
| 已完成 | 查看交付 | 创建后续工作须显式操作 |

每张卡最多一个高强调主操作、一个次操作。暂停、取消、清理隔离区在更多菜单，保留必要确认。状态优先级集中派生，终态、验收、异常、暂停与内部阶段组合必须按后端语义定义，避免不同组件自行判断。

请求未确认前显示提交中；超时显示结果待确认并查询状态，不直接显示失败后允许重复执行。

输入框明确“发给本工作”或“指导这次执行”。查看执行默认只读，点击指导才切换范围。文件、日志和成果引用以可移除片段展示，带来源和目标工作。完成工作后输入不得悄悄重新启动旧执行。

## 5. 关闭、Esc、返回与尺寸调整

不变量：关闭辅助面板不改变工作 ID、筛选、滚动位置、草稿或执行状态；焦点返回打开它的控件；查看历史不改变当前版本。

1. 关闭按钮只关所在面板，不返回首页、不取消运行。
2. Esc 从最上层处理：菜单、对话框、辅助面板；一次只关一层，输入法组合期间不处理。
3. 输入框、编辑器和 iframe 可以先消费 Esc；跨 iframe 只使用校验来源与会话的消息桥接。
4. 未保存编辑保留草稿并提示；丢弃草稿是独立动作，不能按 Esc 就丢内容。
5. 展开后提供恢复分栏，两边阅读位置不变；拖动分隔线配键盘调宽，记住本机宽度偏好。
6. URL 保存工作、对象、版本与详情范围；Back/Forward 恢复状态。直接打开深链接时关闭应回所属工作，不能简单 history.back 到站外。
7. 移动端以单面板全宽打开，显式返回工作，不挤压成两列。

验收路径：打开→滚动→展开→恢复→关闭；Esc；后退/前进；直接深链接；iframe 内操作。核对焦点、位置、草稿、URL 与运行状态。

## 6. 历史：记录、版本、执行尝试分开

工作头部固定历史入口，辅助面板内分为：

- 工作记录：要求修改、决定、分工变化、暂停/继续、验收，默认折叠普通工具噪音，支持人员/类型筛选。
- 成果版本：版本名称、提交人、时间、变更摘要、验证结论、验收状态，明确当前版本。
- 执行尝试：第几次运行、开始/结束、停止原因、关联成果与执行会话。

点历史条目展示当时快照；若仅有事件记录就明确标注，不能用当前任务卡冒充历史。查看旧版本显示“正在查看历史版本”和“回到当前”。比较以文件差异、设计变化、字段差异为单位，关联验证结果。

恢复需求/计划应创建新的当前修订。代码恢复必须是独立且可检查的工作，说明工作区和未提交改动影响。恢复记录不得自动重放工具调用，也不得声称可以撤销外部发布或数据库变化。

前置：审计 Trace、Honey、Git 与工作区保留策略。没有不可变快照就只提供记录，不展示不可兑现的恢复按钮。CAS revision、Git commit、成果版本 ID、执行尝试 ID 分开建模。

## 7. 协同开发：分工、交接与权限

工作头部显示负责人和参与者摘要，点击协作成员，在当前工作内回答：谁在做什么、等谁、改哪些范围、交给谁验收。

分工行包含成员、人/AI、职责、子工作、状态、输出和交接对象。点击后就地展开，保留父工作，不强迫先进入私聊。

动作明确区分：邀请参与项目、给已有成员分配工作、提问、请求评审。加入群聊不等于有改代码权限。邀请界面显示范围及后端真正支持的权限，提交前核对，成功后可查看结果；撤销入口须有服务端能力支持。

先沿用现有 owner/member 与 can_manage 权限。观察者、执行者、审阅者若要细分，先完成后端授权再显示 UI。复制链接不授予权限，无权限页说明原因。

多人编辑按对象 ID 与 revision 提交；冲突保留草稿，显示最新值和差异，再由用户确认。没有 presence 服务时只显示最近活动，不伪造在线状态或实时光标。

多人/多 Bee 改同一仓库时，展示已有写入范围、隔离目录、依赖与集成负责人，字段不存在不凭空推断。冲突呈现在工作里。交接卡包含改动摘要、验证结果、待决事项和请求的下一步。

## 8. 视觉规格与美观

复用现有 --nb-* 主题变量、深浅色及 8/12/16 圆角约定。目标是减少噪音与保持一致，不再添加一层主题系统。

以下是建议规格，实施时截图检查：

| 项目 | 修改建议 |
| --- | --- |
| 字体 | 标题 20–22px，分区 16–18px，正文 14–15px，辅助 12–13px；中文导航用常规字体，等宽仅用于代码/路径/版本 |
| 间距 | 4/8/12/16/24/32px；主区 24px、移动端 16px；卡片内 16px，独立区块间 24px |
| 表面 | 主卡一层轻边框或背景，卡内用间距分组；工具过程用低对比时间线，减少卡套卡 |
| 层次 | 第一眼标题和主操作；第二眼状态、负责人、最近进展；内部阶段/轮次进入详情 |
| 颜色 | 一个强调色，错误红仅用于需处置异常，绿用于完成；状态同时有文字，不能只靠颜色 |
| 路径 | 默认短路径和复制，允许展开完整值；异常时提高可见性，移动端不能只依赖 hover title |
| 尺寸 | 侧栏约 240–264px、沟通区 360–440px、成果占余量；1100px 以下可切单栏，768px 以下默认单栏 |
| 可访问性 | 图标有名称、焦点可见、常用触控目标至少 44px；正文对比度目标 WCAG AA |
| 动效 | 120–180ms，尊重 reduced-motion；轮询不跳位不抢焦点；加载保留容器尺寸，失败就地重试 |

成果正文控制阅读宽度约 65–80 字符，代码和差异可更宽。组级统计退到侧栏，工作详情不重复铺设全群待办条。保留长名称、异常、多成员情况下的布局，不只优化空页面。

## 9. 新建工作与后台运行

新工作先输入目标，可选仓库/目录、文件和验收要求。示例采用修复报错、实现功能、评审改动、调查性能、解释代码；点击只填草稿，不自动发送。

目录要区分项目默认、本工作覆盖、实际隔离执行目录；变更后说明影响新执行还是已有执行，不能只显示一个根目录标签。

只有后端确实持续运行时提示“可以离开页面”。通知按真实配置显示：浏览器通知显式授权，飞书通知配置成功后才承诺；无通知时提供回到待办查看完成结果的路径。

## 10. 实施顺序与代码落点

### P0：现有流程接通

- taskcard.js / workflow.js：标题直达、待验收主操作、统一状态派生、目录短显与展开。
- composer.js / app.js：验收提示限定当前工作；主操作与输入作用域一致；全局待办留在侧栏。
- drill.js / workbench.js / store.js：复用检查面板扩展成果展示，统一关闭、Esc、URL、草稿、焦点与阅读位置。
- colony.css / shell.css / workspace.css：统一间距和层次，减少重复状态、边框、等宽小字；保留主题与移动端。

验收：工作列表到详情一次点击，到成果一次点击；无跨工作验收串场；关闭后位置草稿不变；390px/1280px 无意外横向溢出。用同一批数据记录前后点击数，不虚构效率百分比。

### P1：历史与分工可读

- store.js / drill.js / workbench.js：历史面板、筛选、当前与历史标记。
- manage.js / workflow.js：职责、交接、范围与权限说明。
- colony_api.ex 及相应领域模块：先核对事件、成果、权限、CAS，缺字段才新增分页和版本关联。

验收：翻页不跳读；旧记录真实对应当时状态或明确仅事件记录；并发修改保留草稿；后端拒绝越权；无快照不允许恢复。

### P2：比较、恢复与多人编辑

先完善不可变版本、权限、工作区保护、冲突处理，再提供比较和恢复。在线 presence、实时共编、细粒度权限是独立后端能力，不能只画 UI。现阶段不移除 iframe 执行能力，保留原链接与会话恢复，逐步迁移。

## 11. 验证与未决项

用户覆盖：首次使用者、多工作管理者、需要检查代码的程序员、只读成员。路径覆盖：新建、离开返回、阻塞恢复、验收、历史、协作与权限冲突。

行为验证覆盖 Back/Forward、Esc 层级、焦点恢复、轮询期间草稿、CAS 冲突、重复提交、跨工作异步响应、iframe 来源校验。视觉检查包含桌面、窄屏、深浅主题、长标题与错误态。不以源码字符串断言代替用户路径验证。

Aily 的历史详情、键盘 Esc、版本恢复和协同设置仍待稳定登录环境继续验证；不能据此复制其实现。现有证据已足够推进 P0，P1/P2 依据 newbee 的真实后端合同逐项实施。
