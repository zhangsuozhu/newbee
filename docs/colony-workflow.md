# 任务内的人与多 Bee 协作

群聊的新任务先由负责人只读分析范围和风险。简单明确的任务进入自己的隔离目录实施；需要比较路径的任务邀请最多三只 Bee 独立提案。明确要求“讨论方案”会保留人的选择步骤。

多份提案收齐后自动互评一轮。任务卡并排展示方案、互评和人的补充。管理员可选择一只执行，或勾选两至三只，填写各自交付目标、修改边界、依赖和验证要求后一起实施。普通成员可以补充意见；决定执行者和分工需要管理权限。任务上下文中说“让 @某成员 执行”也会进入同一个版本校验的决策入口。

分工任务各自在独立目录工作。全部子成果提交后，原负责人在自己的目录集成变更、解决冲突并进行组合验证，形成主任务成果。主任务验收同时接受其待验收分工成果。系统不会自动提交、推送或写回原项目。

## 状态与恢复

`triage → executing` 或 `triage → proposing → discussing → choosing → executing → integrating`。

流程保存在主任务的 `workflow` 字段；提案和分工是关联子任务。状态更新、下一阶段派发和群聊事件在同一个 Store 事务中写入。执行决定必须携带当前任务 revision；重复选择、过期回调不会再次开工。普通继续、修订、成果提交入口不能越过提案阶段。现有手工创建的底层 Work 保持原有行为，群聊及创建 API 启用新流程。

初步分析最多尝试三次；独立提案最多三只；互评最多两轮；分析、提案、互评及其人工重试总调用预算为十二次。无效路由会受阻，可重试分析；提案或互评受阻可补充答复并重试当前阶段。暂停沿用群、成员、任务及父任务控制。执行器丢失后的恢复沿用现有 outbox 规则，已接受的外部操作不会未经判断自动重放。

群聊隐藏工具流水和中间分工成果，将任务卡、决策与最终成果放在主要位置；详细调查和执行日志仍可进入会话查看。

## 工作目录

Git 项目先保存当前源码快照（包括未提交和未跟踪的源文件），再建立 detached Git worktree 并覆盖快照。普通目录使用同样的独立快照。快照排除项沿用 `Newbee.Collaboration.Workspace`，因此忽略的依赖和构建缓存可能需要重新安装或生成。工作树路径保存在任务中并在界面展示；目录缺失时报错，不回退到原项目执行。

分析只读和执行目录边界通过任务上下文约束及隔离工作目录实现；这不等同于操作系统级文件沙箱。集成负责人负责检查实际文件与验证证据，系统不能仅凭自然语言总结证明代码正确。

### 实际发现及修复

| 问题 | 证据与结果 |
| --- | --- |
| 媒体图片无法显示 | 原始媒体请求返回401；图片、音视频及下载改用带凭证请求，保持跨域凭证保护。真实登录后同一图片返回200。 |
| 新建群使用连续原生弹窗，创建后可能选错群 | 改为统一表单，按创建响应ID选群；实际创建成功并选中新群。 |
| 首屏初始化异常，任务不自动更新 | `bindPause` 错误嵌套导致 ReferenceError，轮询未启动。修复作用域并让轮询独立于首次渲染启动；实际页面 polling=true。 |
| 模型信息请求阻塞整个首屏 | 观察到 auth.status/host.describe 已返回、llm.models 未返回，群聊仍为空。辅助信息改为后台加载，RPC增加超时，超时提示要求先确认结果，不自动重试写操作。 |
| 刷新回到别的群 | 保存并校验当前群ID；连续刷新保持验收蜂群。 |
| 重绘丢失分工勾选 | 保存每项任务的选择；真实勾选两位后强制重绘仍为两个选中项，随后实际提交分工。 |
| 手机执行任务卡过长 | 390px视口同一任务卡从约5101px降到951px；已确认方案和长判断依据可展开。无横向溢出。增加滚动后可见的当前任务入口。 |
| 分工详情展示内部派发JSON | 正在执行的子工作改为明确的行动提示，完整任务资料留在详情/执行记录。 |
| 子成果提前催人验收 | 人的验收栏排除待集成子成果，子任务标记待负责人集成；最终只提示一件主成果，接受后整体收尾。 |
| Markdown提及崩溃 | 旧函数在真实Chromium DOM中抛出 `span is not defined`。新实现使用文本节点，覆盖重叠名字、特殊字符、code/pre/a排除、文本保留与无HTML注入。 |
| 非控制中断缺少人工恢复入口 | 改为blocked/waiting_for=user且resume_needed=false，受控暂停保留恢复标记。新增AI任务+accepted投递测试：连续两次sweep无新投递、无新会话，人工继续后只新增一次投递。 |

### 对 Bee 协作质量的观察

初步判断曾自行调用 Hive 创建额外审查员并反复等待，绕开了群内编排。观察者在执行会话纠偏，随后群内两个提案及互评正常推进。Workflow 已加强阶段职责：快速路由、禁止二次委派、由编排器推进阶段。该限制是上下文约束，不是操作系统沙箱或模型总 token 硬上限；本次没有做修改后的模型成本对照实验。

一份提案依据后部 legacy 分支推导“任务状态越权”，遗漏了前置授权分支。另一位成员在人的证据质疑后复核并否定该结论，因此没有实施无依据的权限改写。

初版中断修复仍设置 resume_needed=true，新增测试只用了真人任务且没有执行sweep，不能证明不重派发。观察者独立检查后阻断验收，要求负责人修正并补AI投递回归。集成时另发现新增 Workflow 调用缺少 alias，也在验收前修复。多 Bee 互评不能替代调用链核查、实际测试和集成验收。
