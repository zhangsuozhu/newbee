# 蜂群协作 v2：实现与验证

实现位于 `feat/colony-suite` 的 `.newbee/worktrees/colony` 工作树，尚未提交。产品约定见 [协作设计 v2](bee-colony-collaboration-design.md)。旧 HTML 原型不代表现行运行界面。

## 使用

从原 newbee 界面的「蜂群」进入。左侧选择蜂群和成员，中间仍是消息与工作卡，底部保留一个群聊输入框。点击 AI 可以进入原来的真实会话界面，附件、模型、思考和权限交互继续由原界面提供。

- 直接说需求，系统选一位负责人；`@名字` 指定负责人。普通广播不会给每个人重复派同一份工作。需要提案时可明确说 `@all 讨论…`，讨论参与数量受限。
- 真人收到工作后点「我来处理」，用「提交成果」填写结果、验证说明、成果引用和未覆盖范围；管理员在成果卡上「通过」或「打回」。提交结果不会直接把工作标成完成。
- 工作卡可查看目标、约束、验收条件、版本和证据，补充要求，答复后继续，或请其他成员协作。
- 群设置可添加本地 AI、邀请同事、邀请另一台环境、移出成员、退出蜂群和解散蜂群。成员身份与每个蜂群的权限分别保存。
- 上传按钮、拖拽和粘贴接入真实上传接口。附件随工作进入执行上下文，跨环境附件走鉴权分块下载。
- 「能做什么」、工作进度、群设置及暂停按钮始终可发现，不要求先记住命令。

## 配置与跨环境

本地工作使用当前项目环境。真人通过一次性邀请链接填写名字加入，不需要模型、设备身份或执行目录配置。

跨环境使用「群设置 → 邀请另一台 AI 环境」。邀请码内已经包含连接地址、证书指纹和一次性凭据；在另一台 newbee 的「加入蜂群」粘贴，确认名称和允许工作的本地项目目录。无需手工填写 token 或证书指纹。

发起环境必须先具备对方可访问的 HTTPS 地址；默认 `127.0.0.1` 本地服务不能跨主机访问。在实际可访问的 HTTPS 地址上生成邀请，避免把 localhost 链接发给别人。已有 Web 远程启动方法见 [README](../README.md)，例如 `./bin/newbee web --https --host 0.0.0.0 --set-password`。这里没有实现公网穿透、自动开放防火墙或自动信任证书。

邀请码一小时有效、只能使用一次。身份按蜂群隔离，移出或退出会撤销对应凭据。环境连接采用证书指纹钉选，错误指纹不能兑换邀请。远端只能拉取自己的工作与附件，不能用成员凭据操作服务器文件或任意会话。

## 执行与控制

一个工作只有一个当前负责人。工作记录与具体会话分别保存；投递先进入持久化 outbox，由受监督的执行器处理。

- 创建工作不会立即启动 AI 会话。执行器和接收器均检查控制状态；处于暂停的远端也只同步工作，不创建执行会话。
- 接收器写入持久回执后确认接受。同一投递重试不重复排队；接收状态未知时保留工作并等待处理，不自动重放可能产生副作用的请求。
- 群、成员和工作各有独立暂停闸门。恢复群不会解除此前单独暂停的成员或工作。
- 暂停在执行边界生效；已有动作需要执行器确认。未确认时展示暂停中，不能声称已停止。立即中止接入原执行器中断路径。
- 群暂停不会阻止真人说话、接手或提交成果；对真人不显示 AI 正在中止之类的提示。
- 网络失联与未知结果不会触发自动抢占或另一个 AI 重做。远端通过后续同步接续；原环境仍是工作事实的权威。
- 真实执行事件形成证据。成果绑定执行时的工作版本，需求改变后旧版本成果不能通过新验收。失败、阻塞、待验收、完成分别展示。

## 主要代码

| 模块 | 职责 |
|---|---|
| `Colony.Store` | 受监督串行事务；快照写入后才确认成功；重启恢复 |
| `Colony.Work` | 单一负责人、上下文修订、继续工作、协作者、成果与验收 |
| `Colony.Control` | 分范围暂停、中止、恢复、真实执行状态确认 |
| `Colony.Runtime` | 持久投递、延迟启动会话、接收回执与真实事件投影 |
| `Colony.Remote` | TLS 拉取同步、版本和回执、分块附件、暂停确认 |
| `Colony.Membership` / `Conversation` | 一次性邀请、可撤销身份、成员会话与私聊范围 |
| `Colony.Engine` / `Interaction` | 自然语言路由、成员选择、群聊消息与视图聚合 |
| `Web.ColonyApi` | RPC 权限和输入边界 |
| `Web.Session` / `Agent.Loop` | 接收器幂等、排队边界、暂停与中断接入 |
| `priv/web/colony/` | 群聊、成员、工作卡、成果验收、附件与设置 |

持久化位置为 `Newbee.GlobalStore.root()/colonies/store-<MIX_ENV>.json`。身份、控制、投递和工作随快照保存，测试数据与开发数据隔离。

主要新增 RPC 包括 `colony.control`、`colony.invite.create/redeem`、`colony.remote.join/poll/attachment`、`colony.upload.session`、`colony.work.revise/continue/submit/collaborate`。兼容的 `colony.task.*`、`colony.honey.*` 和群管理入口仍由权限层统一约束。

## 验证记录

环境：Elixir 1.20.3 / OTP 29，本工作树。测试关闭自动后台派发，涉及执行器与远端同步的测试显式驱动目标行为，避免测试期间触发真实模型调用。

1. 蜂群与 Web RPC 回归：`MIX_ENV=test mix test test/newbee/colony test/newbee/web/colony_api_test.exs`，65 项通过。覆盖事务与恢复、CAS 修订、分范围暂停、重复投递、丢失接收器、不自动抢占、远端报告归属/去重/版本、真人身份及验收。
2. 实际浏览器：在独立预览服务中走通建群、显示群名、给真人派活、接手、拖拽上传 TXT、带附件发消息、提交成果及限制说明、管理员验收、工作变为完成。还核实了群暂停期间真人可以接手。
3. 两个独立 OS 进程与独立存储根：通过真实 HTTPS/TLS 验证邀请码兑换、错误证书拒绝、邀请码重用拒绝、暂停时无执行会话、恢复后导入、420,000 字节附件分块传输并逐字节核对、受控事件回传、验收和终态同步。两进程位于同一物理主机，执行事件由脚本明确构造；该测试不代表真实模型产出或真实异地主机网络验收。
4. 全量回归：1,255/1,261 通过，13 跳过、14 排除，6 项失败。对失败所在六个文件单独复查，26/29 通过；两个超时不再出现，显式 `MIX_ENV=test` 后终端环境变量断言通过。仍失败的是 RepoMap 的两个 AST 引用解析测试，以及 Hive 工具文档预算测试（4,220 bytes）。这些模块及对应测试相对 HEAD 无改动；全量测试不能标记为全绿。

日志位于 `/tmp/newbee-colony-targeted-tests.log`、`/tmp/newbee-colony-full-tests.log`、`/tmp/newbee-colony-failure-recheck.log`、`/tmp/newbee-colony-tls-{authority,peer}.log`。

TLS 冒烟脚本已保留为 [test/support/colony_tls_smoke.exs](../test/support/colony_tls_smoke.exs)。选一个尚未使用的数据目录，在两个终端分别执行：

```sh
mix run --no-start test/support/colony_tls_smoke.exs authority .newbee/colony-smoke-run
mix run --no-start test/support/colony_tls_smoke.exs peer .newbee/colony-smoke-run
```

脚本在回环地址使用 4576 端口，会创建隔离测试证书及凭据；测试目录包含邀请信息，不应提交。两个进程各自输出 `PASS` 并退出才算成功。该脚本使用受控回执及执行事件，没有触发模型，也不应将它的模拟成果误认成真实研发证据。

## 验证边界

尚未使用真实模型完成一个跨环境研发任务，也未验证实际两台物理主机的路由、防火墙、重启掉电及长时负载。当前结果支持上述功能和协议闭环，不支持宣称模型质量、成本下降或生产可靠性已经得到验证。
