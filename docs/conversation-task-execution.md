# 直接输入任务：自动分工执行

当前产品入口是原项目对话。用户输入目标，newbee 规划分工、分别执行，最后由负责人集成验证。GitHub、评论、Webhook、建群和选择成员都不是这条流程的前提。

## 使用

1. 在现有对话选择项目和模型。
2. 输入一个完整目标，例如：`给这个项目增加 CSV 导出，处理空日期，保持现有格式，补充测试并给出使用说明。`
3. 点击输入框旁的 **分工执行**。也可发送 `分工执行：给这个项目增加 CSV 导出……`。
4. 在原对话查看任务分工。系统先调查项目再生成计划，不要求用户填写子任务、指定执行者或确认内部阶段。独立工作并行；存在依赖的工作等上游交付再执行。
5. 直接在当前输入框补充要求。工作中出现需要业务选择的问题，也在这里回答。继续使用暂停、继续、重试、结束；重试仅恢复失败的分工，其他执行者不重启。
6. 所有分工交付后，负责人读取真实工作目录、集成变更、处理冲突并执行组合验证。原对话显示整体成果、验证与未覆盖范围；查看文件差异后应用到当前项目。

普通聊天仍用 **发送**。没有分工工作时，普通问答不会被自动创建为任务。离开页面或刷新后，从原对话继续查看。

## 界面约定

- 主工作卡只表示一个总任务，展示规划、分工执行、集成验证阶段，以及已交付分工数量。
- 子项显示工作目标、依赖、实际状态和当前活动；内部 Bee ID、调度 JSON、执行会话不进入日常操作。
- 子项交付不等于总任务完成。只有负责人完成集成并产出当前要求版本的成果，才进入整体验收。
- 新要求先显示已收到；模型真正读取后才标记采用。已交付分工保留，新要求同时交给未完成分工并带入最终集成。
- 子项的问题由总任务投影到原对话，答案精确路由到该子项；不让用户切入另一个输入框。
- 来源设置撤出这条主流程。旧来源接口兼容已有数据，配置不是执行总任务所需步骤。

## 执行边界

每次计划为 1–4 项、最多 3 项同时执行。简单工作允许只有一项，不为并行强行拆分。计划必须有明确目标、交付边界和验收要求；依赖必须存在且不能成环。无效计划不会开始子执行者，会说明错误并允许重试。

每项分工和最终集成都使用独立工作目录与确定性执行会话，继承当前对话的模型设置。下游任务只读上游成果，并把需要的依赖变更应用到自己的目录；负责人负责最终合并与组合验证。不会以几段总结拼接代替集成，不自动提交或推送代码。

暂停与结束覆盖所有分工。恢复前核对旧执行者是否已停止，新的执行代次拒绝迟到回执。单项错误可重试，不据此重放其他分工的外部操作。执行结果以真实回执与当前需求版本为准；页面断开不会自动复制工作。
